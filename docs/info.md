# How it works

This project places a complete differential byte transceiver and autonomous loopback tester in one GF180 2x2 analog frame (four tiles, 711.2 x 325.36 micrometres). A native 3.3 V differential transmitter and receiver connect to an 8N1 serial byte engine. Four analog pins provide TX+, TX-, RX+ and RX-. The default line rate is 100 kbit/s from a 1.6 MHz system clock.

SPI registers select ordinary byte transfers or a built-in self-test. Normal mode transmits one software-supplied byte and holds one received byte for software; there is no FIFO or flow control. Self-test generates PRBS8, alternating 55/AA, walking ones, walking zeros or a fixed byte. The receiver has its own synchronizer, start-bit detection and three center samples. Its expected-pattern state advances independently of the transmitter, so a transmitted byte alone cannot produce a passing result.

The complete 32-bit interface is retained. Seven 32-bit counter values report checked bytes, checked payload bits, mismatched bytes, mismatched payload bits, framing errors, receive timeouts and normal-mode receive overruns. Six counters are stored; checked payload bits are derived as saturated eight times checked bytes. A 32-bit target specifies the byte count. A snapshot command captures all counters together for coherent multi-byte SPI reads. Overflow, invalid commands and detected faults set sticky failure state; PASS requires completion of the requested count with no failure or overflow. A run above 536,870,911 bytes would overflow the checked-payload-bit counter and must be split into shorter runs.

The complete GF26e implementation uses 54.8475% digital placement utilization in the 2x2 frame. Local checks pass: 44 RTL/native-mapped/routed functional cases, all nine extracted timing corners, full transistor/resistor LVS, 60 loaded macro simulations and all 12 official shuttle prechecks. GitHub Actions records remote artifact, precheck and PDF results for each commit. Final shuttle integration, package/board behavior and silicon testing remain separate; the project has not been submitted or fabricated. The custom PHY is not qualified as LVDS or RS-485.

# How to test

Connect TX+ (ua[0]) to RX+ (ua[2]), and TX- (ua[1]) to RX- (ua[3]) with two short loopback wires. This exercises the transmitter and receiver on the same project through the shuttle analog access path. These are logical project pi ns; use the final carrier pin map for physical connectors. A compatible USB controller can supply the clock, configure tests and read counters, so functional pass/fail testing does not require an oscilloscope.

Use the board-approved supplies, select the project, provide a 1.6 MHz clock and reset it. The project itself uses VDPWR = 3.3 V and VGND, with no project VAPWR connection. The shuttle's shared analog switches still require their separate global VAPWR rail. Its actual GF26e carrier voltage has not been confirmed; 3.3 V and 5.0 V switch-rail simulation cases are assumptions, not wiring instructions.

SPI mode 0 uses ui[0] for CSn, ui[1] for SCK, ui[2] for MOSI and uo[0] for MISO. Transactions contain a write flag/address byte followed by one data byte. Keep each SCK half-period and the CS-high interval at least eight system clocks. Read identity D8 at address 00 and version 01 at address 01. Configure a nonzero byte count at addresses 08-0B, choose a pattern at 07, then write 01 to command register 03 to start. Wait for DONE in status register 06, write 10 hex to register 03 to snapshot counters, and inspect the result. A passing test has the requested checked-byte count, eight times that many checked payload bits, all error counters zero, and no FAIL or OVERFLOW. Repeat all five patterns and both boost settings. The repository's REGISTERS.md and host/ directory define the full protocol and test procedure.

The GitHub rtl workflow runs the external-pin digital regression. The gds workflow checks the committed source/artifact hashes, packages the custom layout as GDS/OAS/PNG and runs the unchanged official Tiny Tapeout prechecks with the pinned GF26e PDK. The docs workflow validates this metadata and produces a PDF artifact. These workflows do not replace extracted analog simulation, full-transistor LVS or final shuttle integration checks. Implementation sources and pinned local rebuild instructions are included in the repository.

# External hardware

A compatible Tiny Tapeout carrier/controller, USB host and two short loopback wires are needed. Board-specific firmware, supply configuration, connector mapping and package/board loading are not yet validated. Do not add standard differential termination or assume standard-interface electrical compatibility. Digital pass/fail readout does not measure analog swing, common-mode range, noise immunity or a timing eye; those require separate electrical characterization. Final shuttle post-fill verification remains outside the current project checks.
